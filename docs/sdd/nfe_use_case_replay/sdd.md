# sdd:nfe_use_case_replay

## Status
Done

## Goal
Classify the 115 real-world NF-e XMLs in `docs/research_nfe_use_case/` into distinct use cases, replay every scenario against Armazenda **offline** (parser round-trip + builder golden tests), and publish a gap analysis (`docs/research_nfe_use_case/USE_CASES.md`) that drives follow-up feature SDDs. No SEFAZ network traffic is ever generated by this work (SEFAZ network guard rule).

## Background

The corpus (`docs/research_nfe_use_case/`, 5 folders, 115 `.xml` files) was exported from a third-party emitter used by the same farm. Scan findings:

- Every file is a complete `<nfeProc versao="4.00">` (signed `<NFe>` + `<protNFe>`), **authorized** (`cStat=100`), **production** (`tpAmb=1`), **normal emission** (`tpEmis=1`), serie 921, **exactly 1 item** (romaneio-style), same issuer (personal farm producer with CPF in `emit`).
- All 115 files carry the full post-reform IBS/CBS block (`CST=000`, `cClassTrib=000001`, symbolic rates 0.1%/0.9%, `<gMono>` in totals, `<vNFTot>`) — consistent with Armazenda's 2026 constants (`pkg/nfe/defaults/reform.go`).
- **Emission-only corpus:** no `procEventoNFe` (cancellation), no contingency (`tpEmis` 6/7), no denial, no inutilização, no multi-item NF-e.

Exact per-file grouping (from the classification pass):

| # | Use case | natOp/CFOP | finNFe | ICMS | PIS/COFINS | tPag | Files |
|---|----------|------------|--------|------|------------|------|-------|
| G1 | Grain sale, standard — ICMS51 deferral, `infCpl` note art. 573-586 RICMS/MT | 5101 | 1 | 51 | 08 (NT) | 99 | 84 |
| G2 | Sale to order (venda a ordem) | 5118 | 1 | 51 | 08 | 01 | 23 |
| G3 | Return of consumption-material purchase (devolução) | 5556 | 4 | 90 | 90 | 90 | 3 |
| G4 | Return from demonstration | 5913 | 1 | 50 / 41 | 41 | 01 | 2 |
| G5 | Consignment for repair | 5915 | 1 | 41 | 41 | 90 | 1 |
| G6 | Sale of immobilized asset (taxed) | 5551 | 1 | 20 | 20 | 01 | 1 |
| G7 | Other outputs | 5949 | 1 | 41 | 41 | 90 | 1 |

Sub-variants crossing groups: `modFrete` 0 (21) / 1 (84) / 9 (10) with `transporta` + `veicTransp`; destination CNPJ (114) vs CPF (1); item discounts (2 files, only in G3); `indFinal=0`, `indPres=9`, `indIntermed=0` everywhere.

Gaps already spotted in `pkg/nfe/xml/builder.go` (to be confirmed by the golden tests):

- `buildICMS` always emits `ICMS00` for regime normal — real corpus is 93% `ICMS51` (deferral) plus 40/90/20 → SEFAZ would reject the built XML (cStat 215 family: wrong CST for the ICMS00 tag).
- `finNFe` hardcoded `"1"` → devolução (`finNFe=4`) unsupported.
- PIS/COFINS always `PISAliq`/`COFINSAliq` → corpus needs `PISNT`/`COFINSNT` (CST 08) in ~95% of files, plus Outr variants.
- No `dhSaiEnt` emitted (all 115 real files include it; MT requires it for grain sales in practice).

## Requirements

### Functional
1. **Classification:** every one of the 115 XMLs is classified into exactly one use-case group (G1–G7 above plus sub-variant tags) by a deterministic extraction pass; group counts must sum to 115.
2. **USE_CASES.md:** `docs/research_nfe_use_case/USE_CASES.md` documents the taxonomy with counts, one representative access key per group, the sub-variant matrix, and a per-group **use case → Armazenda mapping** (supported / gap / reject-risk) referencing concrete files/functions.
3. **Fixtures:** all 115 XMLs are deterministically anonymized into `pkg/nfe/xml/testdata/realworld/` with a `README.md` and a `manifest.json` (per-file: group, key discriminants). People/companies (names, CPF/CNPJ, emails, phones, addresses, driver names, certificates, protocol numbers) are synthesized with valid check digits; business data (natOp, CFOP, taxes, IBS/CBS, values, dates, modFrete, volumes, infCpl structure) is preserved.
4. **Parser round-trip test:** a table-driven Go test feeds all 115 anonymized files through `nfe_xml.ParseDANFEData` and asserts parse success plus key invariants (access key consistency, item/totals coherence, prot cStat=100).
5. **Builder golden tests:** per use-case group, build the XML from entity inputs derived from representative real values and compare it against the real anonymized XML at DANFE level and tag-structure level, with an explicit per-group allowlist of known diffs (= the gap list). Every allowlisted diff is documented in USE_CASES.md.
6. **No SEFAZ traffic:** nothing in this work dials SEFAZ; the guard (`pkg/nfe/sefaz/guard.go`) is untouched; `NFE_SEFAZ_GUARD=block` semantics unchanged.

### Non-Functional
- The anonymizer is deterministic (same input → byte-identical output) and committed under `pkg/nfe/xml/testdata/realworld/generate.go` so fixtures can be regenerated; `testdata/` is ignored by Go builds so the tool does not affect `go build ./...`.
- Synthetic documents must keep schema-plausible shapes (44-char access key with correct cDV, 15-digit nProt, 8-digit cNF, base64-shaped digests/certs).
- Free text (`infCpl`, `xNome`, synthetic names) must be ASCII-only, matching `SanitizeSchemaString` expectations.
- Tests must not depend on the `docs/` research folder staying put (fixtures are self-contained copies in `testdata/`).
